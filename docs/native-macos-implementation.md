# Peel 原生 macOS 实施记录

日期：2026-10-08。原生版位于 `apps/native-macos`，默认 `npm run dev:desktop` 和 `npm run build` 已切换到原生版本。

## 已完成

- Swift + AppKit 工作台，Scintilla Cocoa 编辑器及 Lexilla JSON/JavaScript 高亮；原生窗口、菜单、文件对话框、剪贴板、全局热键和菜单栏入口。
- 原文、表达式和结果面板；JSON 行号、折叠、校验定位、格式化/压缩、粘贴去转义、查找替换、撤销重做。结果面板可隐藏并释放对应编辑器。
- JavaScriptCore helper 进程，保留 JS data 表达式、纯 JS Promise、JSONPath Plus 和特殊结果处理。死循环可强制终止并恢复；新请求取消旧请求；全应用最多两个 helper 并发。
- ≤1 MiB 文档暂停输入400 ms后自动提取，更大文档手动执行。约1.2秒超时和16 MiB结果上限。
- SQLite 按记录保存、列表元数据分页、正文按需读取、Unicode 标题/正文子串搜索；旧目录/schema1和2迁移、重复导入保护、事务回滚和设置迁移。
- 临时窗口保存/取消/丢弃流程；关闭主窗口后释放工作台，保留菜单栏和热键；重开恢复所选记录。
- 初始化、切换、关闭和退出期间的编辑保护；NUL 文本保真；JSON 大整数原文/键顺序保留与根 null 正确格式化。
- 固定版本和SHA-256校验的原生依赖获取、发行版编译、脚本资源及许可证打包、本机 ad-hoc 签名。

原先考虑的 SwiftUI 工作台已改为 AppKit。首次实机观察到较大的绘制相关分配后，采用更直接的原生控件实现，并通过下述测量检验。最初的高图形分配也会随系统回收而下降，不能把全部变化都归因于框架替换。

## 验证结果

原生核心20个测试通过；旧桌面存储2个、共享包22个测试通过；现有 TypeScript 类型检查通过。Swift Debug/Release 编译、shell语法检查、发行版签名校验通过。

已确认的测试边界：JSON处理、历史存储/迁移/搜索、进程提取。测试覆盖 null、大整数保真、Unicode错误位置、转义、非法JSON、深嵌套、持久化、分页、固定/删除、迁移优先级与幂等、失败重试与回滚、NUL保真、JS/JSONPath、Promise、不可变输入、序列化异常、取消、死循环超时与恢复。

通过实际原生应用验证了粘贴自动排版、中文/emoji、一次撤销/重做、查找替换、JSONPath模式切换和执行、临时窗口保存并关闭、正文和表达式的重启恢复。交互测试修复了分段控件动作绑定和折叠图标的问题。

## 性能证据

基准机：Apple M3 Max，36 GiB，macOS27.0，Xcode27.0。发行版，无Electron/WebView/Node运行时。安装包目录约2.3 MiB。

大历史测试预置1000条×1 MiB正文，随后增加一条约1 MiB的编辑基准文档。后台运行完毕并等待35秒后测空闲内存，关闭主窗口5秒后测常驻内存。数据目录使用自动清理的临时目录，不读取实际用户历史。

| 指标 | 实测 | 约定目标/解释 |
| --- | --- | --- |
| 外部进程启动至文档安装、绘制并可输入 | 512 ms | ≤1秒；包括进程加载，原始报告内部ready为389 ms |
| 约1 MiB文档插入+AppKit重绘 P95 | 6.70 ms | ≤50 ms的诊断参考；不含键盘事件派发和显示器扫描 |
| 主窗口空闲physical footprint | 88.2 MB | ≤100 MB；空闲时无提取helper |
| 关闭主窗口后的physical footprint | 74.4 MB | 菜单栏/热键常驻；编辑器、正文、撤销栈释放 |
| 全部相关进程的采样峰值footprint | 320.9 MB | 包含图形与提取瞬时开销；空闲门槛不等于峰值门槛 |
| 约1 MiB JSON校验/格式化 | 1.64 / 15.38 ms | 后台处理；一次组件基准 |
| 约10 MiB JSON校验/格式化 | 17.26 / 159.01 ms | 压力样例；完成格式化往返校验 |

原始GUI基准：[2026-10-08-large-history.json](native-macos-performance/2026-10-08-large-history.json)。可用 `python3 apps/native-macos/scripts/benchmark.py --record-bytes 1048576` 重现；默认每条正文10 KB。

另三次新进程测试内部ready为252、230、225 ms，完整进程启动到退出为412、334、305 ms。构建后首次运行/系统状态变化时曾出现1.3–2.8秒的启动；这些波动仍需跟踪，不能声称任何启动都在1秒内。没有测量旧Electron的同输入基准，因此不报告相对降幅。

曾使用单行压缩JSON作编辑压力样例，未优化时P95约124 ms；随后通过文档版本号替代整份Unicode文本比较，把常规排版JSON的P95降至当前值。优化后的超长单行编辑尚未完成独立完整基准。

## Standards

审查基点：`e801733`。未发现适用硬标准违反。最初发现主窗口保存重复查询历史列表的判断性气味，已将跨窗口刷新回调限定为临时窗口；复审确认修复，无未解决的Standards发现。

## Spec

最初发现四项问题：保存/切换/退出期间新编辑可被覆盖、初始化前可输入但会被覆盖、NUL导致文本截断、序列化错误变成超时。已修复模型/控件保护、版本检查、显式UTF-8长度读写和Promise异常链，并增加回归测试。复审未发现未解决的阻塞性Spec问题。

后续复审确认模式切换、所选记录恢复、菜单初始化等待、折叠标记和基准读取修复。恢复的记录如果不在前100条元数据中，正文仍会恢复，侧栏需要加载后续页才有对应高亮。

最后将保存、正文分析和提取分别使用对应的版本号，避免修改标题使有效的分析或提取结果被丢弃；复审确认取消和旧结果保护仍有效。

## 当前限制

- 最低目标为macOS14；实际运行仅验证了本机macOS27，仍需要macOS14实机兼容验证。
- 完整键盘到屏幕的延迟、首次安装启动、优化后的超长单行、3个以上临时窗口压力尚未完成完整专项基准。
- 峰值内存可超过100 MB；本轮达成的是约定的空闲门槛。
- JS完整语言服务/补全、多光标、浏览器fetch等API不在首版承诺内。
- 当前产物用于本机自用；公开分发的签名、公证和升级尚未配置。
- Electron工作区继续用于迁移对照，旧数据文件保留；默认使用的是原生构建和启动。
